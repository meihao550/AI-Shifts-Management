# 時間カバレッジを「ちょうど」から「必要人数〜必要人数+α」に緩め、短時間勤務者を配置可能にする

[ADR-0003](0003-weekly-shift-count-hard-constraint.md) では過剰配置（おかしなシフト）を避けるため時間カバレッジを実質「ちょうど(`==`)」にした。しかしフラットな需要では、境界時間（例: 16:00台）を埋めるフルシフトの従業員が周辺時間も満たすため、**短い勤務可能時間帯（例 9-15 / 9-16）の従業員を足すと過剰になり `==` で禁止され、1枠も入れなかった**。

過剰を全面禁止すると短時間勤務者が構造的に使えず、全面許可すると供給過多で暴走する。折衷として、各時間の配置人数を **`必要人数 ≤ 配置 ≤ 必要人数 + α`（α=1）** のハード範囲に収め、過剰は弱ペナルティ（`SURPLUS_WEIGHT`、平準化より十分小さい）で嫌う。これにより「働きたい人（＝空きのある短時間勤務者や、公平化で入れたい人）は入れる」を叶えつつ、**「1枠に殺到」の暴走は α で頭打ち**にする。過剰は誰かを働かせられる時だけ +α を使い、無駄には出さない。

## Considered Options

- **過剰を全面禁止（`==`、ADR-0003 当初）**（却下）: 短時間勤務者が構造的に配置不能。
- **過剰を全面許可（ソフトペナルティのみ）**（却下）: 供給過多で以前の「おかしすぎる」過剰が再発。
- **α を可変にする**（一部採用）: まず α=1 のグローバル既定。将来ルール設定画面から変更可能にする余地を残す。

## Consequences

- ADR-0003 の「過剰ゼロ」方針を「+α まで許容」に改訂。3段フォールバックのカバレッジは全段で `[必要人数, 必要人数+α]`（第3段はさらに不足も許容）。
- α はグローバル定数 `SURPLUS_TOLERANCE = 1`（`scheduler.py`）。過剰ペナルティは `SURPLUS_WEIGHT`。
- 短い窓（例 9-15 / 9-16）の従業員が、実需要下でも配置されるようになる。

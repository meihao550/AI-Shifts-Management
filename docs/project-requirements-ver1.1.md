## 0. この文書について（最初に読む）

### 0.1 何を・なぜ作るか

飲食店（先方）の**月次シフト作成を自動化**するアプリ。現状は管理者が手作業で毎月シフトを組んでおり、
**有給・希望・必要人数・人間関係などの制約**を頭の中で調整している。これを

- **生成AI**：その月特有の事情を自然言語で受け取り、制約（JSON）に変換
- **CP-SAT（制約プログラミング）**：全制約を同時に解いてシフトを出力

の2段構えで置き換え、**30分以内**でシフトを作れるようにする。あわせて**人件費の自動計算**も行う。

### 0.2 全体像（データの流れ）

```
従業員マスタ（時給・保険区分・ペア制約・研修生 等）
        ＋
有給申請（毎月15日締め）＋ シフト希望（❌・出勤可能時間）
        ↓                     ↑ アプリ入力 or 紙→オーナー代理入力
   今月の事情（自然言語）→ 生成AIで制約化
        ↓
   CP-SAT で求解 → シフト表（生成）
        ↓
   手動編集（制約を満たす候補をプルダウン）
        ↓
   人件費計算 ／ PDF・Excel 出力
```

# <a id="p1"></a>第 I 部　背景と目的

## <a id="s1"></a>1. 開発の経緯・目的

### 1.1 前回プロダクトで残った課題

- 従来システムのリファクタリングに留まり、**労力削減**という目的を達成できなかった
- **AIを使って楽をしたい**という目的に沿えなかった
- 機械系(機械学習系)は学習コストが高いため、**学習コストの少ないもの**を作りたい

### 1.2 課題を解決することで得られる効果

- スケジューリング問題の解法とAIを活用し、**30分以内**でシフト作成を行えるようにする
- 通常業務に集中させることで**利益増加**を見込める
- 学習コストが少なく操作でき、**ミスによるシステム破壊を防げる**
- 担当者が変更しても、引き続き同じシステムを使用できる

## <a id="s2"></a>2. プロジェクト名

**AI-Shifts-Management**（仮決定）

## <a id="s3"></a>3. 現状の業務フロー（As-Is）

先方ヒアリングにより判明した、現在の手作業でのシフト作成手順。**システムはこの流れをなぞる形で設計する。**

```
① 毎月15日まで  従業員から有給申請を受け付ける
        ↓
② 有給を先に入力する
        ↓
③ 各従業員がシフトカレンダーに記入
     ・出勤可能な日と時間
     ・絶対に出勤できない日（❌）
        ↓
④ 管理者がシフトを組む
     4-1. 深夜班を決める（ほぼ時間固定）
     4-2. 夜班を決める（ほぼ時間固定）
     4-3. 足りない箇所に「どこでも出れる人」を入れる
     4-4. 最後に朝班を決める（最も変動が大きい）
        ↓
⑤ 完成
```

**設計上の含意**

- **有給入力がシフト生成より前**に来る。有給日は「出勤不可」としてCP-SATに渡す必要がある
- 深夜・夜が先に決まるのは制約が強いため。CP-SATは同時に解くので順序自体は不要だが、**深夜・夜の制約を強め、朝を緩める**重み付けの根拠になる
- 「どこでも出れる人」は出勤可能時間の登録がない従業員として表現する

# <a id="p2"></a>第 II 部　要件

## <a id="s4"></a>4. 開発スコープ

### F-1: AIシフト機能

- 生成AIとCP-SATによる制約プログラミングによってシフトを作成する
- **生成AI**：その月特有の事情を自然言語で入力すると、それを解釈して制約として判断する。自然言語を処理し、JSON形式に変換して制約とする
- **CP-SAT**：従業員ごとの制約をすべて組み合わせ、実際のスケジューリング問題を解いてシフトを出力する

### F-2: 人件費自動計算機能

- 全体の1ヶ月の人件費と、その日1日の人件費を計算する
- 労働時間から社会保険・雇用保険を適用するかどうかを判断する

### F-3: 有給管理機能 【新規】

- 従業員ごとに**有給1日あたりの金額**を1つ登録する
- シフト作成時にセルへ「有給」と入力すると、その従業員の金額が自動で入る
- 有給日は勤務時間に加算せず、人件費にのみ加算する

### F-4: 従業員別出勤可能時間の管理 【新規】

- 出勤時間が固定の従業員 → **登録する**
- 出勤時間が流動的な従業員 → **登録しない**（＝どの時間でも配置可能として扱う）
- 加えて、日ごとの出勤可能時間・絶対勤務不可日を入力できる

| is_over_40            | bool   | 介護保険の判定用                                      |

## <a id="s6"></a>6. シフトパターンと必要人数

### 6.1 基本パターン

| 区分 | 時間帯       | 拘束 | 休憩       | 実働                 |
| ---- | ------------ | ---- | ---------- | -------------------- |
| 朝   | 9:00 - 17:00 | 8h   | **要確認** | **要確認**           |
| 夜   | 17:00 - 1:00 | 8h   | **要確認** | **要確認**           |
| 深夜 | 1:00 - 9:00  | 8h   | 60分       | **7h**（先方確認済） |

### 6.2 Wワークパターン（不定時刻）

仕事を掛け持ちしている従業員は勤務時刻が固定されず、以下のパターンから配置する。

9〜15 / 9〜16 / 10〜17 / 10〜18 / 12〜20 / 15〜23 / 18〜20 / 18〜1 / 20〜1

> ヒアリングでは金・土・祝の追加要員として **22:00〜1:00** の言及もあったが、先方資料のパターン一覧には含まれていない。**要確認**（付録A #9）。

### 6.3 曜日区分別の必要人数

| 曜日区分             | 朝  | 夜  | 深夜 | 合計    |
| -------------------- | --- | --- | ---- | ------- |
| **平日**（月〜木）   | 2人 | 2人 | 1人  | **5人** |
| **金・土・日・祝日** | 3人 | 3人 | 1人  | **7人** |

深夜は曜日を問わず**毎日1人**。増減するのは朝と夜のみ。**日曜は金・土・祝と同じ扱い**（先方資料により確定）。

### 6.4 曜日区分ごとの充当パターン

#### 平日（月〜木）

| 枠   | 人数 | 充当するパターン                                                                     |
| ---- | ---- | ------------------------------------------------------------------------------------ |
| 深夜 | 1人  | 1:00 - 9:00                                                                          |
| 夜   | 2人  | ① 17:00-1:00 × 2人<br>② 17:00-1:00 × 1人 ＋（18:00-20:00 と 20:00-1:00 の2人で分割） |
| 朝   | 2人  | 9:00-17:00 / 9:00-16:00 / 10:00-17:00 から個人の登録に応じて                         |

> 夜の②は、1人分の枠を2人で分け合う形。**人数カウント上は「1人分」か「2人」か要確認**（付録A #10）。

#### 金・土・日・祝日

| 枠   | 人数 | 充当するパターン                                                               |
| ---- | ---- | ------------------------------------------------------------------------------ |
| 深夜 | 1人  | 1:00 - 9:00（平日と同じ）                                                      |
| 夜   | 3人  | 平日の構成 ＋ **追加1人**：15:00-23:00 / 12:00-20:00 / 22:00-1:00 など（不定） |
| 朝   | 3人  | 平日と同じパターンから1人増                                                    |

> 追加要員の時間帯が固定されないため、**「夜に3人」を時刻でどう判定するか**が設計上の論点（→ 13章）。

### 6.5 時間帯ごとの実運用（ヒアリング内容）

| 時間帯           | 実態                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| 深夜             | **毎日1人**。1:00-9:00 で確定。実働7時間                                     |
| 夜               | 17:00-1:00 が2人。または1人＋（18:00-20:00 と 20:00-1:00）の分割             |
| 金・土・祝の追加 | 15:00-23:00 / 12:00-20:00 / 22:00-1:00 などバラバラ                          |
| 朝               | 9:00-17:00 / 9:00-16:00 / 10:00-17:00 と人により異なる。**最も変動が大きい** |

## <a id="s8"></a>8. 画面・機能要件

### 8.1 ログイン画面

- **Google Workspace認証（OAuth）**
- シフト管理者／一般社員で機能を制限する
- ログイン後はダッシュボードへ遷移

### 8.2 ダッシュボード

ログイン後の最初の画面。今月のシフトを表示し、各機能への入り口となる。

- 1ヶ月の人件費を表示
- 従業員個人の**総勤務時間（休憩を除く）** を表示
- **保険区分ごとの色分け表示**（社保＋雇用／雇用のみ／未加入が一目で分かること）
- 各従業員の**月間勤務時間が保険区分の上限に対して何%か**を表示
- この画面ではシフトを編集できない（表示のみ）
- **毎月26日**に通知する
- 「シフトを編集する」ボタンでシフト表画面へ遷移

### 8.3 従業員管理画面

| 入力項目                       | 備考                                                     |
| ------------------------------ | -------------------------------------------------------- |
| メールアドレス                 | Google Workspace。登録されれば従業員も利用可能           |
| 名前 / 年齢                    |                                                          |
| 時給                           |                                                          |
| 交通費                         |                                                          |
| **有給1日あたりの金額**        | 1人につき1つ                                             |
| **保険区分**                   | 3分類から選択                                            |
| **40歳以上か**                 | 介護保険判定用                                           |
| メインで入るシフト             |                                                          |
| 週に何回入るか                 |                                                          |
| **出勤時間の登録有無**         | 固定 → 曜日別パターンを登録／流動 → 登録しない           |
| **ペア制約**                   | 「組ませられない人（利益が下がる）」「一緒にしたいペア」 |

| 在籍状況                       | 研修生・退職者の除外に使用                               |

### 8.4 有給入力画面 【新規】

シフト生成の**前段**に位置する画面。

- 毎月15日締めの有給申請を入力する
- 従業員 × 日付 のカレンダー形式で「有給」をマークする
- マークした日は自動で従業員マスタの有給金額が適用される
- 入力後、シフト表画面へ引き継がれる

### 8.5 シフト希望入力画面 【新規】

- 従業員 × 日付のカレンダーに、以下を入力する
  - ❌（絶対勤務不可日）
  - 出勤可能な時間帯（例：19:00〜25:00）
  - 入りたいシフト
- 固定パターン登録済みの従業員は初期値が自動入力される
- 20人 × 31日の入力になるため、**一括入力・コピー機能を用意する**
- **入力経路は2系統**（→ 10.2）：アプリを使える従業員は自分で入力／使えない従業員は紙で記入し、オーナーが代理入力

### 8.6 シフト表画面（メイン）

**生成前**

- 有給・希望入力の内容を確認
- 「シフト作成」ボタンで生成開始
- 生成の進捗を表示

**生成後**

- カレンダー形式で表示。曜日の自動入力、土日祝の色分け
- 手動編集：セルを押すとプルダウンリストで選択
  - **プルダウンには制約を満たす従業員のみを、優先度順に表示する**
- 「有給」を選択すると、その従業員の有給金額が自動で入る
- 変更時に人件費・勤務時間をリアルタイム再計算
- PDF / Excel に出力（印刷プレビュー画面へ遷移）

### 8.7 人件費計算画面

シフト表（この画面からの変更は不可）と計算結果を表示する。すべて表形式。

### 9.1 人件費の定義

> 人件費 ＝「**その人に関わる全ての金額**」

| 構成要素              | 備考                           |
| --------------------- | ------------------------------ |
| 基本賃金              | 時給 × 勤務時間（休憩を除く）  |
| 割増賃金              | 深夜割増など。**含める**       |
| 交通費                |                                |
| 有給                  | 有給日数 × 有給1日あたりの金額 |
| 社会保険料 事業主負担 | 保険区分による                 |
| 雇用保険料 事業主負担 | 保険区分による                 |
| 労災保険料            | **全員対象・全額事業主負担**   |

## <a id="s10"></a>10. 追加要件（ver1.1 で追記）

ヒアリングで新たに判明・確定した要件。既存章の該当箇所と対応づけて整理する。

### 10.1 有給関連

- 各従業員の**有給1日あたりの金額**を、従業員管理画面から従業員ごとに登録する（→ F-3 / 8.3）
- シフト表画面で「有給」を選択すると、その従業員の有給金額が**人件費に自動反映**される（→ 8.6 / 9.1）

### 10.2 シフト希望の入力経路（デジタルデバイド対応）

従業員の IT リテラシーに応じて、入力経路を2系統用意する。いずれも最終的に同じデータに集約する。

| 対象                   | 入力方法                                        |
| ---------------------- | ----------------------------------------------- |
| アプリを使える従業員   | アプリからシフト希望を直接入力する              |
| アプリを使えない従業員 | 紙で記入 → **オーナーが代理でアプリに登録する** |

### 10.3 ペア制約のハード制約化

- 「この2人を組み合わせると利益が下がる」という人間関係上のルールを追加する
- これを**ハード制約（絶対に守る）へ格上げ**する（→ 既存の `forbidden` ペア＝H-6）
- オーナーは従業員管理画面で、各従業員に「**組ませられない人**」を登録する（→ 8.3 ペア制約）

### 10.4 従業員ごとのNG設定

- **入れない時間帯（NG時間帯）** を従業員管理画面で定義する（→ 5.3 `availabilities` / H-4）
- **NGシフト**は休日として登録する
- 休みが確定している従業員は、従業員管理画面から**固定休のスケジュールを登録**できるようにする

### 10.5 シフトパターンのロジック再設計

- シフトパターン（シフト時間）の割り当てロジックを再設計する（→ 6章、13章 枠カウント方式の論点）

### 10.6 研修生の扱い

- 研修生は通常従業員の**0.5人分の戦力**として扱う。必要人数の充足判定にこの係数を反映させる仕組み（ギミック）を設ける（→ H-1）

### 10.7 ロール／区分変数の再設計【要検討】

従来の `isAdmin`（管理者フラグ）だけでロールを判定していたが、保険区分や研修生の別で処理を分けたい。従業員マスタのロール項目として以下の区分変数を持たせる案。

| 変数（例）  | 区分                                     |
| ----------- | ---------------------------------------- |
| `isBoth`    | 社保＋雇用保険 加入者                    |
| `isHire`    | 雇用保険のみ 加入者                      |
| `isNotBoth` | 社保・雇用保険とも未加入者（36協定含む） |
| （研修生）  | 研修生フラグ                             |

> **要検討**（付録A #12）：既存の `employees.insurance_type`（enum、→ 5.1）と役割が重複する。フラグを新設するのか、既存 enum ＋ `is_trainee` で表現するのかを設計時に統一する。

## <a id="s12"></a>12. 領域間の接続点（実装前に合意する）

並行開発を止めないために、**実装より先に合意しておく項目**。

### 12.1 API契約は OpenAPI を正とする

- バックエンドが**先にエンドポイントとスキーマだけ定義**する（中身は未実装でよい）
- フロントは `openapi-typescript` で型を生成し、MSW 等のモックで先行実装する
- スキーマ変更は**必ず PR で共有**する。無断変更は禁止

### 12.2 日跨ぎ時刻の表現

シフトの 17:00〜翌1:00 をどう表現するか。**決めないと必ずバグる。**

| 案  | 表現                                                              | 評価                                                     |
| --- | ----------------------------------------------------------------- | -------------------------------------------------------- |
| A   | `start: "17:00"`, `end: "01:00"`                                  | 終了 < 開始 で日跨ぎと判定。境界処理を毎回書くことになる |
| B   | `start_min: 1020`, `end_min: 1500`（0時起点の分数、25:00 = 1500） | **推奨。** 比較・差分計算が単純な整数演算で済む          |

**B を採用する。** API では分数（integer）でやりとりし、表示時にフロントで `25:00` 形式へ変換する。

### 12.3 タイムゾーン

- **すべて JST で統一**する。UTC変換は行わない
- 日付は `YYYY-MM-DD` の文字列、時刻は上記の分数で表現する

### 12.4 命名規則

- API のフィールド名は `snake_case`（Python 側に合わせる）
- フロント内部は `camelCase`。**変換はAPIクライアント層の1箇所でのみ行う**

### 12.5 エラーレスポンスの形式

```json
{
  "error_code": "INFEASIBLE",
  "message": "制約を満たすシフトが見つかりませんでした",
  "details": { "conflicting_constraints": ["H-1", "H-7"] }
}
```

エラー表示をフロント側で個別に書かせないよう、**形式を統一する**。

## <a id="s13"></a>13. 設計上の論点：枠カウントか時間カバレッジか

例外パターンには **12:00-20:00** のように、朝枠（9-17）と夜枠（17-1）をまたぐものがある。この人を「朝1人」と数えるのか「夜1人」と数えるのかで、必要人数の判定が変わる。

| 方式                      | 内容                                                                  | 長所                                 | 短所                                                        |
| ------------------------- | --------------------------------------------------------------------- | ------------------------------------ | ----------------------------------------------------------- |
| **A. 枠カウント方式**     | 各パターンに所属枠（朝／夜／深夜）を1つ割り当て、枠ごとに人数を数える | 実装が単純。現在の運用の考え方に近い | 12:00-20:00 を夜扱いにすると、17時までの時間帯が実質1人減る |
| **B. 時間カバレッジ方式** | 時刻を30分等の単位に区切り、各時間帯に必要人数がいるかを判定する      | 実態に忠実。人数の穴が発生しない     | 制約数が増える。必要人数を時間帯単位で再定義する必要がある  |

**Phase 1 は A（枠カウント方式）で実装する。** 先方の現在の運用がこの考え方であり、また Phase 1 の目的は動くものを早く出すことにあるため。B は Phase 3 以降の改善候補とする。

A を採用する場合、各シフトパターンに所属枠を定義する必要がある（`shift_patterns.slot`、→ 5.4）。

暫定の割り当て（**要確認**、付録A #11）：

| パターン                                                 | 所属枠 |
| -------------------------------------------------------- | ------ |
| 9〜17 / 9〜16 / 9〜15 / 10〜17 / 10〜18                  | 朝     |
| 12〜20 / 15〜23 / 17〜1 / 18〜20 / 18〜1 / 20〜1 / 22〜1 | 夜     |
| 1〜9                                                     | 深夜   |

- ヘッダーバーに画面名を表示し、現在いる画面がバー上でわかるようにする

- 従業員データは個人情報を含むため、**テストデータを含めて厳重に管理する**

## <a id="s21"></a>21. 人件費計算の段階的算入方針

> **先方方針（段階的算入）**
> 有給・交通費・社会保険料は本来「その人に関わる全ての金額」に含まれるが、計算が複雑になるため、**初期の人件費表では除外し、後から追加加算する**方針とする。
>
> - **第1段階**：時給 × 勤務時間 ＋ 割増賃金 のみを表示する
> - **第2段階**：有給・交通費・社会保険料等を加算する
>
> 設計上は最初から全項目を持てる構造にしておき、**表示側で ON/OFF を切り替える**ことで、後から追加加算する際の手戻りを防ぐ。

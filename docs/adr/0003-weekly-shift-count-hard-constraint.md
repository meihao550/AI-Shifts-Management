# 週シフト回数を週単位のハード制約にし、競合時は過剰配置を避けて週回数を先に緩める

> **改訂(ADR-0005)**: 本ADRの「時間別必要人数は `==`（過剰ゼロ）」は、短時間勤務者が構造的に配置できない問題のため撤回。現在は「必要人数 ≤ 配置 ≤ 必要人数 + α」（α=1）に緩めている。以下の `==` の記述は α=0 の特殊ケースと読み替えること。

従来 `weekly_shifts` は「週回数 × 週数」を**月合計のソフト目標**（weight=1）として扱うだけで、「どの週も必ずN回」を保証していなかった。「週2回入りたい人は絶対2回」という要件に応えるため、**日曜起点の各週ごとに `weekly_shifts` ちょうどN回のハード制約**へ変更する。適用対象は新フラグ **`weekly_shifts_pinned`** を持つ従業員に限定し、**新規従業員はデフォルトON**（既存従業員はOFFのまま、マイグレーションで一括ONにはしない）。フラグOFFの従業員は従来どおりソフト目標。

- **月末月初の半端な週**（生成期間に7日揃わない週）は、`round(N × 対象日数/7)` を目安とする**ソフト目標**に落とす。半端な週にフルNを課すと物理的に破綻するため。
- 時間別必要人数(`==`)も引き続きハードで、両者は両立しない週が出る。競合時は**必要人数ちょうど（＝過剰配置を出さない）を優先**し、週回数を先にソフトへ落とす。過剰配置（必要人数を超える人員）は運用上「おかしなシフト」で無価値なため、個人の週回数保証より過剰回避を上位に置く（週回数を満たせない人は警告する）。

## Considered Options

- **全従業員に一律で週回数ハード**（却下）: 全員分の窓・必要人数が噛み合わず、インフィージブルが激増する。フラグで対象を絞る。
- **必要人数を絶対優先し、週回数はソフトのまま**（却下）: 「週回数はハード」という要件に反する。第1段では両方ハードを試すことで、両立する週はちょうどNを保証する。
- **両方ハードのまま、解けなければ生成失敗（割当ゼロ）**（却下）: 部分解も出ず運用不能。手動修正の前提に合わない。
- **競合時に個人の週回数を最優先**（初期案・却下）: 供給過多（Σ週回数 > 必要人数）の週で必要人数を超える過剰配置が多発し、非現実的なシフトになった。過剰を出すより先に週回数を諦める方針へ改めた。

## Consequences

生成は3段のフォールバックで**常に部分解を返し**、不足箇所を警告する:

1. 週回数(完全週=ちょうどN) ＋ 必要人数(==) を**両方ハード**で解く。
2. 解けなければ**必要人数(==)は維持**し、週回数を**ソフトに降格**する。供給過多の週は各人の回数が自然に減り、必要人数を超える過剰配置は生じない。「◯◯さんは週N回入れませんでした」を警告。
3. なお不可（必要人数ちょうども満たせない＝真の人手不足）なら、**必要人数をスラック化**し「◯月◯日 △時：△人不足」を警告。

過剰配置を出さないことを優先するため、pinned でも供給過多の週は週回数を満たせないことがある。運用は部分解を受け取り、警告箇所を**手動修正**する前提とする。

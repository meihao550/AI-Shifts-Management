# 「確定出勤」を availability 種別 mandatory として追加する

「この曜日/この日は必ず入れたい」（例: 深夜の曜日固定担当）というニーズに応え、休日/希望日(出勤ソフト)/有給に加えて**確定出勤**をカレンダーの登録種別に追加する。希望日(`preferred`)は「入りやすくする弱いnudge＝出勤ソフト」、確定出勤(`mandatory`)は「その日は必ず1シフト」を意味する。

- 具体日付の `EmployeeAvailability.kind` に **`mandatory`** を追加（[ADR-0007](0007-fixed-weekly-calendar.md) の共有カレンダー上で登録）。
- **時間窓（1時間単位）**: 希望日と同じく `note`「HH:MM-HH:MM」で開始・終了を指定できる。窓ありは「窓に収まるパターン」に限定して必ず1シフト（`Σ_{p: pat_hours(p) ⊆ 窓} x[e,d,p] == 1`）。窓なしはその日の任意パターン。窓に収まるパターンが1つも無い場合はそのハード段を解なしにして診断段へ回す。
- **確定出勤の制約強度**: 通常段(第1・2段)では**ハード**。診断段(第3段, 不足許容)では、勤務可能時間帯・連勤・保険上限などで物理的に不可能な場合に解が消えないよう、**強いソフトペナルティ**（`MANDATORY_WEIGHT`）に緩め、満たせなかった (従業員, 日) を警告する。

編集UIはシフト表と共有の月カレンダー上で、日付クリックのモーダル（種別＝確定出勤＋開始/終了時刻）、または「曜日で一括登録（確定出勤 ＋ 時間帯）」で設定する。

## Considered Options

- **常にハード（緩めない）**: 窓に合うパターンが無い等で解が消える。第3段だけソフト化して部分解＋警告を返す方が運用に合う。
- **確定出勤を持たず preferred のみ**（却下）: 「必ず入れたい」を表現できない。
- **曜日テンプレの status(work_hard)として持つ**（初期案・却下）: 曜日テンプレ自体を廃止し具体日付に統一したため（ADR-0007）、種別は availability 側に置く。

## Consequences

- `availability_kind` enum に `mandatory` を追加。`AvailabilitySpec.kind` も同様。スケジューラに `_mandatory_lookup()` と対応制約を追加。
- 確定出勤は不足(coverage shortage)の次に強い優先度で守られるが、絶対保証ではない（満たせなければ警告）。

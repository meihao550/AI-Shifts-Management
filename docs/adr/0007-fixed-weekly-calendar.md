# 固定カレンダーはシフト表と共有する具体日付カレンダー＋曜日一括で実現する

木曜だけ出勤・他は休み、といった従業員は毎月同じ曜日パターンになる。毎月その休日を手入力するのは手間で、シフト作成時間を圧迫する。当初は曜日テンプレ（`EmployeeFixedSchedule`）を持ち生成時に展開する設計にしたが、ユーザーの意図は**シフト表の「休日・希望日」カレンダーを流用して同期させる**ことだった。

そこで**専用の曜日テンプレは廃止**し、従業員管理の「カレンダー」は**シフト表と同じ月カレンダー（`AvailabilityCalendar`）を従業員固定で表示**する。編集は具体日付の `EmployeeAvailability`（休日/希望日/確定出勤/有給）で、**同じデータをシフト表と共有＝即同期**する。「毎月流用」は**曜日で一括登録**ボタン（例: 木曜=確定出勤・他=休日 を当月へ適用）で賄う。

- 生成時の受け皿は既存の `_unavailable_lookup()`/`_preferred_lookup()`/`_mandatory_lookup()`。固定由来の特別扱いは不要（具体日付として保存済み）。
- 深夜の曜日固定などは「その曜日を確定出勤で一括登録」で表現する。

## Considered Options

- **曜日テンプレを保持し生成時に展開（初期案・却下）**: シフト表カレンダーと別データになり「同期」しない。ユーザーの想定と食い違う。二重管理にもなる。
- **具体日付ベース＋曜日一括（採用）**: データ源泉が1つ（`EmployeeAvailability`）で、シフト表と自動同期。毎月は曜日一括ボタンで流用。
- **完全自動の毎月流用**（見送り）: 具体日付方式では月ごとに一括ボタンを押す運用。自動反復が要れば別途テンプレを再導入する。

## Consequences

- `employee_fixed_schedules` テーブルと `fixed_schedule_status` enum は削除。
- 従業員ページのカレンダーとシフト表のカレンダーは同一コンポーネント・同一データ。
- 「確定出勤」は [ADR-0009](0009-mandatory-fixed-work.md) の `mandatory` 種別として扱う。

# 週シフト回数を週単位のハード制約にし、競合時は必要人数より個人の週回数を優先する

従来 `weekly_shifts` は「週回数 × 週数」を**月合計のソフト目標**（weight=1）として扱うだけで、「どの週も必ずN回」を保証していなかった。「週2回入りたい人は絶対2回」という要件に応えるため、**日曜起点の各週ごとに `weekly_shifts` ちょうどN回のハード制約**へ変更する。適用対象は新フラグ **`weekly_shifts_pinned`** を持つ従業員に限定し、**新規従業員はデフォルトON**（既存従業員はOFFのまま、マイグレーションで一括ONにはしない）。フラグOFFの従業員は従来どおりソフト目標。

- **月末月初の半端な週**（生成期間に7日揃わない週）は、`round(N × 対象日数/7)` を目安とする**ソフト目標**に落とす。半端な週にフルNを課すと物理的に破綻するため。
- 時間別必要人数(`==`)も引き続きハードであり、両者は両立しない週が必ず出る。競合時は**個人の週回数を優先**し、必要人数側を崩す（＝人員過不足を許容）。要件で「絶対ちょうどN回」を最優先としているため。

## Considered Options

- **全従業員に一律で週回数ハード**（却下）: 全員分の窓・必要人数が噛み合わず、インフィージブルが激増する。フラグで対象を絞る。
- **必要人数を絶対優先し、週回数はソフトのまま**（却下）: 「週回数はハード」という要件に反する。
- **両方ハードのまま、解けなければ生成失敗（割当ゼロ）**（却下）: 部分解も出ず運用不能。手動修正の前提に合わない。

## Consequences

生成は3段のフォールバックで**常に部分解を返し**、不足箇所を警告する:

1. 週回数(完全週=ちょうどN) ＋ 必要人数(==) を**両方ハード**で解く。
2. 解けなければ**必要人数をスラック化**（過不足許容・週回数はハード維持）。「◯月◯日 △時：△人不足」を警告。
3. なお不可（従業員の窓・休みで週回数が物理的に不可能）なら、その従業員のその週だけ**週回数をソフトに降格**し「◯◯さんは週N回入れませんでした」を警告。

個人の週回数を守るため、生成結果が必要人数に対して過不足になり得る。運用は部分解を受け取り、警告箇所を**手動修正**する前提とする。

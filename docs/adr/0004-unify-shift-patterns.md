# 基本/Wワークのパターン区別を撤廃し、全シフトパターンを1プールに統合する

従来 `ShiftPattern.is_basic` で「基本パターン(全員配置可)」と「Wワーク専用パターン(掛け持ち従業員のみ)」を分けていた。しかし配置は1時間単位の**勤務可能時間帯(窓)**でハードに制御しており、パターンの区別は不要なうえ実害があった: (1) ユーザーが追加したパターンは自動的にWワーク専用になり通常従業員が入れない、(2) 短い窓(例 9:00-16:00)の通常従業員は、窓に収まるのがWワークパターンだけのため**1枠も入れない**。

よって `is_basic` を撤廃し、**全パターンを1つのプールに統合**する。誰でも窓に収まる限りどのパターンにも入れる。朝/夜/深夜は開始時刻からの自動判定(`infer_category`)による区分として残す。掛け持ちを表す `is_dual_worker` フラグは**目印として残すが配置には影響しない**（`DUAL_WWORK_WEIGHT` の寄せボーナスは撤去。ロジックはコメントで残置）。

## Considered Options

- **`is_basic` を残し、ユーザー追加パターンも基本扱いにする**（却下）: 配置は窓で制御済みで、区別自体が二重管理。Wワークパターンの意味も曖昧になる。
- **Wワークパターンは掛け持ち従業員のみ（現状維持）**（却下）: 短い窓の通常従業員が配置不能になる実害が続く。

## Consequences

- DBは `shift_patterns.is_basic` 列を drop（過去の割当には影響なし）。
- `is_dual_worker` は属性ラベルのみになる（給与や将来機能で使う余地は残す）。
- ただし**これだけでは短い窓の従業員が配置される保証はない**（時間カバレッジ `==` の別問題が残る）。それは [ADR-0005](0005-coverage-surplus-tolerance.md) で対応する。

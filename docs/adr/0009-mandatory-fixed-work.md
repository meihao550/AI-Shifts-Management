# 固定カレンダーの「出勤」を確定出勤(ハード)と出勤ソフトから選べるようにする

[ADR-0007](0007-fixed-weekly-calendar.md) では固定カレンダーの「出勤」を preferred（弱いnudge）としてのみ扱い、強制出勤は無しにした。しかし「この曜日は必ず入れたい」（例: 深夜の曜日固定担当）というニーズがあり、出勤を**確定出勤（ハード）／出勤ソフト**から選べるようにする。

- 固定カレンダーの状態を `off` / `work`(出勤ソフト) / `work_hard`(確定出勤) の3種に拡張。
- 生成時の展開: `work_hard` → 新しい availability 種別 **`mandatory`**（その日は必ず1シフト）。`work` は従来どおり preferred。`off` は unavailable。
- **確定出勤の制約強度**: 通常段(第1・2段)では**ハード**（`Σ_p x[e,d,p] == 1`）。診断段(第3段, 不足許容)では、勤務可能時間帯・連勤・保険上限などで物理的に不可能な場合に解が消えないよう、**強いソフトペナルティ**（`MANDATORY_WEIGHT`）に緩め、満たせなかった (従業員, 日) を警告する。

編集UIは専用ページ内の**モーダル**で曜日ごとに 確定出勤/出勤ソフト/休み/指定なし を選ぶ。

## Considered Options

- **常にハード（緩めない）**: 窓に合うパターンが無い等で解が消える。第3段だけソフト化して部分解＋警告を返す方が運用に合う。
- **出勤は常にソフトのまま（ADR-0007）**: 「必ず入れたい」を表現できない。ユーザー要望により却下。
- **セレクトで直接4択**（却下）: ユーザーが明示的にモーダル遷移を希望。

## Consequences

- DB enum `fixed_schedule_status` に `work_hard` を追加。
- `AvailabilitySpec.kind` に `mandatory` を追加。スケジューラに `_mandatory_lookup()` と対応制約を追加。
- 確定出勤は不足(coverage shortage)の次に強い優先度で守られるが、絶対保証ではない（満たせなければ警告）。

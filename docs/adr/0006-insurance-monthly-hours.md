# 保険区分をマスタ属性化し、月間実働時間をハードに制約する

従来 `insurance_status` は人件費計算時に実働時間から**逆算**していた（≥120h→社保 等）。要件では保険区分は「管理者が設定するマスタ属性」であり、それに応じて**シフト生成時に月間実働時間を制約**したい（社保加入者は120h以上、雇用保険のみは80〜119h、未加入は79h以下）。

そこで従業員に `insurance_type`（`social`/`employment`/`none`、既定 `none`）を追加し、スケジューラで各従業員の月間実働分 `Σ x[e,d,p]·worked_minutes(p)` に上下限を課す。人件費表示（`PayrollRow.insurance_status`）もマスタ属性を優先する（未設定時のみ従来の実働時間推定にフォールバック）。

- **上限（過労側・法令準拠）は常にハード**: 雇用 ≤119h / なし ≤79h。上限違反はほぼ常に回避可能で、超過は制度上不可なため。
- **下限（不足側）は週回数(ADR-0003)と同じ扱い**: `weekly_hard` の段（第1段）ではハード、緩和段ではソフト（不足分にペナルティ＋「◯◯さんは下限◯hに達していません」警告）。下限は需要不足で物理的に満たせないことがあるため、既存の3段フォールバックで緩める。

## Considered Options

- **従来どおり実働時間から自動判定のまま**（却下）: 生成時に時間を制御できず、要件（区分ごとの時間制約）を満たせない。マスタ属性という要件定義とも矛盾。
- **上限・下限とも常にハード**（却下）: 社保の下限120hは需要不足時に容易にインフィージブルとなり、解が出ない。下限は緩和可能にする。
- **全てソフト目標**（却下）: 「なし」区分の79h上限は制度上の上限で、超過は許容不可。上限はハードが必要。

## Consequences

- `PatternSpec` に `worked_minutes`（実働分＝スパン−休憩、深夜跨ぎ考慮）を追加。`worked_minutes_of()` で算出し `shifts.py` から渡す。
- DBに `employees.insurance_type`（`server_default='none'`）を追加。
- 社保などの下限が満たせない月は、下限をソフトに緩めて部分解＋警告を返す（週回数と同じ運用）。
- 週回数は「シフト数」、保険は「実働時間」で別軸に効く（両者は独立の制約）。

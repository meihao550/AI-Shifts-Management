# 「全員休み（休業日）」を closed_dates としてハード制約化する

「◯日は全員休み」と自然言語で指示しても、従来は LLM が各従業員の `hard_unavailable` に展開できず（多人数の ID 列挙は困難）、`date_notes`（参考メモ＝非強制）止まりで実際には配置されてしまう問題があった。

そこで **休業日(closed_dates)** という概念を新設し、LLM スキーマに `closed_dates: ["YYYY-MM-DD"]` を追加。SYSTEM_PROMPT で「全員休み／休業／定休日は closed_dates に入れる」と誘導する。スケジューラ(`ShiftScheduler`)では休業日を**全従業員のその日を unavailable に展開**し、既存の不可制約でハードに配置ゼロにする。必要人数(カバレッジ)は休業日では課さない（全員休みと必要人数HARDの矛盾で解なしになるのを防ぐ）。

数式: 決定変数 `x[e,d,p]∈{0,1}`（従業員 e が 日 d にパターン p で勤務なら1）に対し、休業日集合 C について
`x[e,d,p] = 0  (∀e, ∀d∈C, ∀p)`、かつカバレッジ等式は `d∈D\C` のみに課す。

## Considered Options

- **date_notes のまま（参考情報）**（却下）: 強制力が無く、全員休みが守られない。
- **全従業員ぶんの hard_unavailable を LLM に列挙させる**（却下）: 人数が多いと LLM が取りこぼし、脆い。
- **closed_dates を新設しハード化**（採用）: 1 日付でソルバー側が全従業員へ展開でき、確実。個別の勤務不可は従来どおり `hard_unavailable` を使う。
